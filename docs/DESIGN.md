2D 방치형 RPG 핵심 로직 기획서 (MVP 범위)
0. 문서 목적 및 범위
이 문서는 Unity 2D 프로젝트에서 방치형 RPG의 핵심 로직 3가지를 구현하기 위한 기획서다.
AI 협업 프로세스(프롬프트/컨텍스트/루프 엔지니어링) 연구를 위한 실험용 기획서이므로, 아래 범위를 반드시 지킨다.
포함 범위 (반드시 구현)

1. 플레이어 캐릭터 컨트롤러 (횡스크롤 이동 + 점프) — 아래 시스템들의 기반
2. 타일맵 기반 레벨 (기본 지형 + 공중 발판 + 원웨이 플랫폼)
3. 자동전투 상태머신 (Auto Battle FSM)
4. 스탯/데미지 계산 파이프라인
5. 오프라인 방치 보상 계산

제외 범위 (이번 산출물에 포함하지 않음)

* 장비 강화, 인벤토리, 뽑기(가챠), 상점 UI
* 파티/동료 시스템
* 네트워크/서버 연동
* 사운드, 파티클 등 연출 요소 (있으면 좋지만 필수 아님)
* 메인 메뉴, 세이브 슬롯 선택 등 부가 UI

1. 게임 개요

* 장르: 2D 횡스크롤 방치형 RPG (메이플스토리류 방치형 게임 참고)
* 시점: 사이드뷰 2D
* 핵심 루프: 캐릭터가 맵을 자동으로 돌아다니며 몬스터를 자동으로 처치 → 경험치/골드 획득 → 접속하지 않아도 시간에 비례해 보상 누적
* 플레이어 개입: 이번 범위에서는 자동전투가 기본이며, 수동 조작(좌우 이동+점프)은 캐릭터 컨트롤러 자체의 기능으로 구현하되, 자동전투 FSM이 이 이동/점프 기능을 그대로 호출해서 사용한다. 즉 "수동 조작용 입력 처리"와 "AI가 이동을 명령하는 로직"이 같은 이동 함수를 공유하는 구조로 설계한다.

2. 플레이어 캐릭터 컨트롤러
2.1 기본 이동

* Rigidbody2D 기반 물리 이동 (Transform 직접 조작 금지)
* 좌우 이동: 목표 방향으로 즉시 속도 전환 (가속/감속 없음)
* `moveSpeed` (public float, 기본값 5): Inspector에서 조정 가능
* 이동 방향에 따라 SpriteRenderer.flipX로 좌우 반전

2.2 점프

* `jumpForce` (public float, 기본값 8): Rigidbody2D.AddForce(Impulse) 방식
* 접지 판정: Physics2D.OverlapCircle로 발밑 groundCheck 포인트에서 판정
* 공중에서 재점프 불가 (isGrounded 체크 필수)
* 점프 중에도 좌우 이동 가능해야 함

2.3 아래로 점프(드롭다운) — 원웨이 플랫폼 통과

* 원웨이 플랫폼(아래에서 위로는 통과 가능, 위에서는 착지 가능한 발판) 위에 서 있을 때, 아래 방향 입력 + 점프 입력을 동시에 주면 일시적으로 해당 플랫폼의 콜라이더를 무시하고 아래로 낙하
* 구현 방식: `PlatformEffector2D` + `Collider2D.isTrigger` 토글, 또는 `Physics2D.IgnoreCollision`을 짧은 시간(예: 0.3초) 동안 적용 후 복원
* 자동전투 FSM에서도 이 기능을 호출할 수 있어야 함 (아래층 몬스터에게 이동할 때 사용)

2.4 이동 API 설계 (자동전투와 공유하기 위한 요구사항)

* 좌우 이동, 점프, 드롭다운 기능은 외부(자동전투 FSM 포함)에서 호출 가능한 public 함수로 노출
   * 예: `MoveHorizontal(float direction)`, `Jump()`, `DropDown()`
* 수동 입력(새 Input System)은 이 함수들을 호출하는 하나의 "호출자"일 뿐이고, 자동전투 FSM도 동일한 함수를 호출하는 또 다른 "호출자"로 설계한다 (입력 로직과 이동 로직을 분리)

3. 타일맵 / 레벨 구성
3.1 기본 지형

* Unity Tilemap 사용, 일반 지형은 Tilemap Collider 2D로 충돌 처리
* 최소 1개 스테이지: 바닥이 있는 기본 평지 + 공중에 떠 있는 발판 2~3개 배치

3.2 공중 발판 (일반 플랫폼)

* 위/아래 모두 막혀있는 일반 발판 (점프해서 올라가야만 도달 가능)
* 캐릭터와 몬스터 모두 이 발판 위에 배치될 수 있어야 함

3.3 원웨이 플랫폼 (아래에서 점프 통과 가능한 발판)

* `PlatformEffector2D` 컴포넌트를 활용한 원웨이 플랫폼
* 아래에서 위로는 그냥 점프로 통과, 위에 착지하면 발판처럼 작동
* 위에서 아래로는 2.3의 드롭다운 기능으로만 통과 가능

3.4 레벨 규모 (MVP 기준)

* 가로로 긴 단일 스테이지 1개면 충분 (경계선은 Camera Confiner 또는 간단한 X축 제한으로 처리)
* 지형 구성 예시: `[바닥] - [원웨이 플랫폼] - [공중 일반 발판] - [원웨이 플랫폼] - [바닥]` 형태로, 자동전투 FSM이 상/하/좌/우로 이동해야 몬스터에게 도달할 수 있는 구조

4. 자동전투 상태머신 (Auto Battle FSM)
4.1 상태 정의

```
Idle → Move → Attack → Loot → Idle (순환)

```

* Idle: 살아있는 몬스터를 탐색
* Move: 가장 가까운 살아있는 몬스터 방향으로 이동 (2.4의 MoveHorizontal/Jump/DropDown 함수 활용, 필요시 점프해서 발판 오르내림)
* Attack: 공격 사거리 내 진입 시 공격 실행 (일정 주기로 데미지 계산 파이프라인 호출)
* Loot: 몬스터 처치 후 드롭 아이템/골드 자동 획득

4.2 몬스터 탐지 및 타겟팅

* 씬 내 몬스터는 별도 스포너가 관리 (몬스터 개별 오브젝트를 FindObjectsOfType으로 매 프레임 탐색하지 않도록, 스포너가 리스트로 관리)
* 타겟 선정 기준: 살아있는 몬스터 중 가장 가까운 대상

4.3 이동/점프 판단 로직

* 목표 몬스터가 현재 위치보다 위쪽 발판에 있으면 점프로 접근
* 목표 몬스터가 아래쪽 원웨이 플랫폼 너머에 있으면 드롭다운으로 접근
* (MVP 범위에서는 정교한 경로탐색 AI는 필요 없음 — "목표가 나보다 위에 있으면 점프, 아래고 원웨이 플랫폼이면 드롭다운" 정도의 단순 휴리스틱으로 충분)

4.4 최적화 요구사항

* 몬스터/이펙트/데미지 텍스트는 Object Pooling으로 관리 (Instantiate/Destroy 반복 금지)
* 상태 전이는 매 프레임 무거운 연산 없이 처리

5. 스탯 / 데미지 계산 파이프라인
5.1 레이어드 스탯 구조

* 캐릭터 스탯은 "기본값 + 여러 수정자(Modifier)"로 구성
* 수정자 종류: Flat(고정값 더하기), PercentAdd(퍼센트 가산), PercentMultiply(퍼센트 곱연산)
* 스탯이 실제로 변경될 때만 최종값을 재계산하는 Dirty Flag 패턴 적용 (매 프레임 재계산 금지)

5.2 관리 대상 스탯 (MVP 기준 최소 세트)

* 공격력 (AttackPower)
* 방어력 (Defense)
* 최대 체력 (MaxHP)
* 크리티컬 확률 (CritRate)
* 이동속도 (MoveSpeed) — 2.1의 moveSpeed와 연동

5.3 데미지 계산 공식

```
최종 데미지 = (공격력 - 방어력 보정치) × 크리티컬 배율(발동 시 1.5배) × 기타 % 증가 배율

```

* 크리티컬 발동 여부는 CritRate 확률에 따라 매 공격마다 판정

5.4 몬스터 스탯

* 몬스터도 동일한 스탯 구조(공격력/방어력/HP)를 최소한으로 가짐 (플레이어와 완전히 같은 시스템을 재사용해도 무방)

6. 오프라인 방치 보상
6.1 계산 방식

* 실시간 시뮬레이션이 아니라, 재접속 시점에 경과 시간을 계산해서 수학적으로 보상 산출
* 앱 종료 시각을 저장 → 재접속 시 `(현재 시각 - 종료 시각)`으로 경과 시간 계산
* 초당 처치율(예: 현재 스테이지에서 자동전투 시 분당 처치 수 / 60) × 경과 시간(초) = 획득 경험치/골드

6.2 제약 조건

* 최대 보상 시간 캡 적용 (예: 최대 8시간까지만 인정, 그 이상은 캡으로 고정)
* 시간 되돌리기 악용 방지: 현재 시각이 저장된 마지막 시각보다 이전이면 오프라인 보상 계산을 건너뜀

6.3 UI

* 재접속 시 "획득한 보상" 팝업으로 표시 (숫자 카운트업 애니메이션은 선택사항, MVP에서는 텍스트 표시만으로 충분)
* 게임 실행 시 테스트 해볼 수 있도록 화면에 Login/Logout 토글 버튼을 추가할 것

7. 데이터 구조 (참고용 최소 스펙)

```csharp
// 스탯 컨테이너 (5.1 관련)
public class StatContainer
{
    public float baseAttackPower;
    public float baseDefense;
    public float baseMaxHP;
    public float baseCritRate;
    // 수정자 리스트 및 최종값 캐시는 구현 시 자유롭게 설계
}

// 몬스터 데이터
public class MonsterData
{
    public string monsterId;
    public float hp;
    public float attackPower;
    public float defense;
    public int expReward;
    public int goldReward;
}

// 오프라인 보상 계산 결과
public class OfflineRewardResult
{
    public float elapsedSeconds;
    public int gainedExp;
    public int gainedGold;
}

```

위 구조는 강제 스펙이 아니라 최소 참고안이며, 구현 과정에서 자유롭게 확장 가능하다.
8. 권장 구현 순서

1. 플레이어 컨트롤러 + 타일맵 (2장, 3장) — 이동/점프/드롭다운이 되는 기본 무대 완성
2. 오프라인 보상 계산 (6장) — 독립적으로 구현 가능, 코드량이 적어 검증이 쉬움
3. 자동전투 FSM (4장) — 2장에서 만든 이동 API를 그대로 활용
4. 스탯/데미지 파이프라인 (5장) — 4장의 Attack 상태에서 실제로 사용

* [ ] 자동전투 FSM이 스스로 몬스터를 찾아 이동(점프/드롭다운 포함)하고 처치하는가?
